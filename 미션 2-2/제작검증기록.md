### 선택한 결과물과 근거

**사용자가 선택한 결과물은 AI A(ChatGPT)이다.** 아래는 이번 확인으로 그 선택을 뒷받침하는 근거이며, 사용자가 직접 말하지 않은 취향이나 사용 경험을 대신 작성한 것은 아니다.

ChatGPT 제작본은 기본 단일·복수 검색에서 추천 5개를 생성했고, 가입대상과 나이 조건을 별도로 적용했다. 특히 ‘강아지’ 검색에서는 반려견 상품 1개만 남겼고, ‘30세’ 검색에서는 확인되지 않은 연령을 임의로 통과시키지 않았다. 반면 Gemini 제작본은 이 두 검색에서 전체 50개를 조건 일치로 처리했다. 따라서 **검색 조건에 맞지 않는 상품을 제외하는 기획 의도를 더 충실히 반영한 ChatGPT 제작본을 선택한 결과물로 기록한다.**

입력 편의에서도 차이가 있었다. ChatGPT는 검색창에 단어를 입력한 뒤 바로 검색하기를 실행해도 해당 단어를 등록하여 검색했다. Gemini는 먼저 Enter 또는 추가로 등록해야 검색이 진행됐다. 이는 기획서가 정한 Enter 등록 흐름과 별개로 확인한 편의성 차이이다.

단, ChatGPT의 모든 기능과 추천 정확성이 검증 완료된 것은 아니다. 화면 잘림·실제 클릭·인쇄·실기기 동작, 전체 추천 점수 및 순위의 정확성은 추가 확인이 필요하다.

## 기획서와 웹페이지 대조 검증

저장소의 최신 기획서와 두 HTML의 Git blob SHA를 다시 확인했다. 세 파일 모두 앞서 검증한 버전과 동일하므로 기존 실행 결과를 해당 원본의 검증 근거로 사용했다. 새로 브라우저 테스트를 통과했다고 기록하지 않는다.

판정에서 **로직 확인**은 원본 JavaScript 실행으로 확인한 범위, **소스 확인**은 구현 코드만 확인한 범위, **미확인**은 실제 화면 검증이 남은 범위를 의미한다.

**전체 완료 판정은 보류한다.** AI A를 선택한 사실과 검색 로직 검증 결과는 기록하되, 실제 화면·브라우저 검증이 끝난 것으로 처리하지 않는다. 기획서 원문과 두 HTML은 변경하지 않았다.

## 테스트 기록

### 실행 환경과 한계

- Node.js `v24.22.1`의 `vm`에서 두 HTML의 원본 `<script>`를 각각 실행했다.
- 문서 요소, 안내창, 스크롤 등 브라우저 기능은 최소 대체 객체로 제공했다. 실제 검색·입력·카드 생성 코드는 바꾸지 않았다.
- 정상 시나리오 10개, 예외 입력 5개를 각각 동일하게 실행했다. 생성된 카드 수, 검색어, 안내 문구, 조건 목록과 상품명을 확인했다.
- 이 방식은 **JavaScript 로직 테스트**다. 실제 DOM 렌더링, 사용자 클릭, 폰트, 화면 너비, 스크롤, 브라우저 인쇄 결과를 검증하지 않는다.
- 자동 브라우저는 실행 중 `socket() failed: Operation not permitted` 오류로 종료됐다. 공유 브라우저의 로컬 HTML 열기도 URL 정책상 제한됐다. 따라서 브라우저 실행 성공이나 모바일 테스트 통과로 기록하지 않는다.
- 보험사 공식 자료·현재 판매 여부·약관의 정확성을 이번 작업에서 재검증하지 않았다. 아래 판정은 내장 DB와 기획 규칙의 소프트웨어 동작에 관한 것이다.

- A는 760px 이하에서 비교표를 세로 형태로 바꾸고, 420px 이하에서 검색창·버튼 배치를 조정한다. B는 640px 이하에서 비교표 대신 모바일 카드를 표시하도록 작성되어 있다.

## 수정 기록

### 추가 발견 문제 — 두 제작본의 모바일 검색 진행 실패

- 발견한 문제: 사용자가 먼저 수행한 테스트 3에서 두 HTML 모두 모바일 Enter 등록을 하지 못해 검색을 진행하지 못했다고 보고했다.
- AI에게 전달한 요청: 이번에는 결과 기록 및 GitHub 커밋을 요청했다. HTML 수정 요청과 구분한다.
- 수정 후 테스트 결과: 미실시.
- 수정 이유: 사용자가 모바일에서 검색어를 등록하고 결과를 확인하는 핵심 작업을 완료하지 못한다.
- 원인·상태: 원인 미확인 / 모바일 3번 실패 보고 / 수정 미진행.


> 이번 요청은 두 결과물 확인·테스트·기록 작성이다. HTML 수정은 진행하지 않았다. 아래는 실제로 발견한 문제와 수정 필요 사항이며, AI에게 전달한 수정 요청이나 수정 후 성공 결과를 만들어 넣지 않았다.

> 위 세 항목은 선택하지 않은 Gemini 제작본의 비교 과정에서 발견한 문제이다. 선택한 ChatGPT 제작본의 수정 완료 3건을 대신하는 기록이 아니다. 선택본을 개선하는 단계에서는 실제 수정 요청·버전·재검증 결과를 별도로 작성해야 한다.

## 사용자 테스트

- 테스트 참여자: 사용자 본인.
- 진행한 작업: 테스트 3(모바일 조건 변경)을 먼저 진행하여 두 HTML의 검색어 등록·검색을 시도했다.
- 사용자의 행동과 질문: 두 모바일 화면을 캡처해 제공했으며 “두 파일 모두 Enter를 못해서 검색을 못함”이라고 보고했다. 구체적인 입력 단어와 터치 순서는 확인되지 않았다.
- 받은 피드백: 모바일에서 검색을 진행할 수 없음. 테스트 3을 먼저 진행했으므로 1·2번 완료로 기록하면 안 됨.
- 반영 내용과 결과: 모바일 검색 실패를 3번 결과에 반영하고, A/B 비교 문서와 캡처 2개를 연결했다. 사용자 1·2번 테스트는 미실시로 구분했다.
- 해결 상태: 기록 반영 완료, HTML 수정 및 재테스트 미진행.
- 결과물 선택: 기존에 사용자가 선택한 ChatGPT를 유지하되 모바일 테스트 통과로 처리하지 않는다.
